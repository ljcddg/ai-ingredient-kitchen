# 烹饪常识知识库

生成菜谱时注入的「操作规程」片段。回答的是**"这一步为什么这么做"**，
和参考菜谱（回答"这道菜长什么样"）互不替代。

## 为什么不用向量库

条目只有十几条，召回靠标签词面匹配就够准；为十几条数据建 embedding 索引、
再拉一个 embedding 服务，是拿运维复杂度换 0 精度收益。等条目过百再考虑。

## 一条规则长什么样

```json
{
  "id": "salt-timing",
  "priority": 8,
  "tags": ["通用", "调味", "盐"],
  "text": "盐要分次后放：炒菜在食材断生后再放盐……"
}
```

| 字段 | 作用 |
|---|---|
| `id` | 稳定标识。**落库到 `t_ai_generation_record.knowledge_rule_ids`，改名等于断掉历史统计** |
| `priority` | 同分时的排序依据（0~9）。没有它，通用类永远是文件最前面那三条被选中，后面补的条目永远轮不到 |
| `tags` | 召回用。`通用` 给 0.5 基础分；写食材类别（`蔬菜`/`肉类`/`水产`/`蛋奶`/`豆制品`/`主食`/`调料`/`乳品`/`果香`）可拿满 1.0；也可写口味词（`清淡`/`酸辣`）或约束词（`少油`/`减盐`） |
| `text` | 注入提示词的一句话。**写成可执行的动作，不写原理科普** —— 小模型只照着做，不会推理 |

## 召回与排序

`knowledge.py::CookingKnowledge.select()`：

```
score = 命中的类别数 + 命中的额外词数 + (通用 ? 0.5 : 0)
排序：score ↓ → priority ↓ → 文件顺序 ↑
只取前 3 条（MAX_RULES）
```

最后那档"文件顺序"是为了**稳定性**：同一请求两次生成必须注入同一批常识，
否则 A/B 对比里"生成质量波动"会混进"知识注入波动"，实验就解释不清。

## 加一条规则的检查清单

1. `id` 不与现有重复，且以后不改名；
2. `text` 是可执行动作（"水开下锅，断生就捞"），不是"焯水很重要"这种废话；
3. 数值类结论（盐 5g、油 25~30g、蔬菜 300g）**必须能指到来源**，不要凭印象写；
4. 加完跑 `pytest tests/test_knowledge.py` —— 里面断言了条目数下限与字段完整性。

## 来源

条目按公开资料**改写**为操作规程，不做原文摘录：

- 《中国居民膳食指南(2022)》平衡膳食八准则（中国营养学会）—— 盐 ≤5g/天、油 25~30g/天、
  蔬菜 ≥300g/天、动物性食物 120~200g/天等数值依据
  <https://www.cnsoc.org/chpolicy/0522202018.html>
- 中国居民平衡膳食宝塔(2022)
  <https://dg.cnsoc.org/article/04/RMAbPdrjQ6CGWTwmo62hQg.html>
- 中餐基本技法（焯水 / 上浆 / 勾芡 / 火候 / 调味顺序）公开科普整理

> ⚠️ 这些是**通用烹饪常识**，不是医学或营养学处方。规则里出现的用量是针对"一道家常菜"的
> 合理区间，不构成个体化营养建议。

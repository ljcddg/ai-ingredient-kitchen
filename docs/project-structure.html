1. 项目总览

一个 Spring Cloud 微服务 + Vue 前端的「AI 做菜」应用：用户选食材 → 先检索菜库命中高质量直接返回，否则 AI 生成 → 校验发布进公共菜库 → 被搜索 / 排行 / 收藏 / 评分，形成「用户既是消费者也是生产者」的闭环。

业务名AI 灵感厨房（project0914） 根包com.apesource；父 pom project0914:1.0.0（packaging=pom，自建父 pom 不继承 spring-boot-starter-parent） 技术栈Boot 3.2.4Cloud 2023.0.1SCA 2023.0.1.0JDK 17MyBatis-Plus 3.5.5jjwt 0.12.5Redisson 3.26.1Elasticsearch 7.16.2Ollama gemma4:e2b 统一约定一律 jakarta.*；所有 Long 序列化为字符串（防前端 JS 精度丢失）；主键雪花 ID（IdType.ASSIGN_ID）；逻辑删除 @TableLogic 前端两套并存：原生 frontend/（无构建）与 Vue 版 frontend-vue/（Vite+Vue3，当前主用）

2. common-service（公共模块）

被所有微服务（含网关）依赖的公共 jar，提供 JWT 工具、统一响应、业务异常、认证常量与 Jackson 序列化约定。自身不含业务实体。

文件类型作用
config/JsonAutoConfiguration.java配置类@AutoConfiguration：把 Jackson 的 Long/long 统一序列化为字符串，避免前端丢失雪花 ID 精度。
constant/AuthConstants.java常量类认证「契约中心」：jwt 配置键名、claim key（userId/username）、请求头名（X-User-Id/X-Username）、Bearer 前缀。
exception/BusinessException.java异常业务异常基类（带 code），校验失败时抛出，由 @RestControllerAdvice 转成 Result.fail。
result/Result.java响应体统一响应包装 Result<T>（code/message/data），含 success/fail/unauthorized(401)/forbidden(403) 静态工厂。
util/JwtUtil.java工具类jjwt 0.12.x 纯静态 JWT 工具：生成/解析/校验 token、剥离 Bearer 前缀；由使用方 @Bean 自行实例化（非 Spring Bean）。
resources/META-INF/spring/...AutoConfiguration.imports自动配置清单声明 JsonAutoConfiguration 自动生效，依赖方无需 @ComponentScan。
classDiagram class Result~T~{ +Integer code +String message +T data +success() +fail() +unauthorized() } class BusinessException{ +Integer code } class JwtUtil{ +generateToken() +parseToken() +resolveToken() } class AuthConstants{ <> JWT_SECRET_PROPERTY CLAIM_USER_ID HEADER_USER_ID TOKEN_PREFIX } class JsonAutoConfiguration{ +longToStringCustomizer() } JwtUtil ..> AuthConstants : 引用键名

设计点：凡是同时出现在两个服务的字符串（头名 / claim key / 密钥键名）都提到 AuthConstants，避免「登录成功却全接口 401」；JwtUtil 不标 @Component，由 account 与 gateway 各自 @Bean new，靠共享 jwt.secret 保证验签一致。

3. gateway（网关）

Spring Cloud Gateway（WebFlux 响应式）。统一做 JWT 校验与身份透传，下游业务服务无需各自写拦截器。路由 / 白名单在 Nacos gateway.yaml，密钥类在本地 application.yml。

文件类型作用
GatewayApplication.java启动类网关入口 @SpringBootApplication，启动扫描加载其余组件。
GatewayStartupChecker.java自检ApplicationRunner：启动后调 AuthProperties.validate() 打印白名单 / 密钥一致性自检，降低「全员 401」排障成本。
config/AuthProperties.java配置绑定 gateway.auth.*（总开关 + 免认证白名单），isWhiteListed(path) 用 AntPathMatcher 匹配；validate() 启动校验。
config/JwtConfig.java配置@Bean 创建网关侧 JwtUtil（读 jwt.secret/jwt.expire-millis）。
filter/JwtAuthGlobalFilter.java全局过滤器GlobalFilter + Ordered（order=-100）：取 token → 校验 → 先删外部传入的 X-User-Id/X-Username 再写网关校验值 → 转发；白名单用「剥掉路由前缀后」的路径匹配。
resources/application.yml配置应用名、Nacos 地址、spring.config.import 拉 gateway.yaml、本地 jwt.secret（必须与 account 逐字一致）。
classDiagram class JwtAuthGlobalFilter{ +filter() +getOrder() -100 } class AuthProperties{ +isWhiteListed() +validate() } class JwtConfig{ +jwtUtil() } class JwtUtil class Result class AuthConstants JwtAuthGlobalFilter --> JwtUtil : 校验 JwtAuthGlobalFilter --> AuthProperties : 开关/白名单 JwtAuthGlobalFilter --> Result : 401 响应 JwtAuthGlobalFilter --> AuthConstants : 头名/claim JwtConfig ..> JwtUtil : @Bean 创建 AuthProperties ..> AuthConstants : 键名 GatewayStartupChecker --> AuthProperties : validate

四个核心设计点：① 用 GlobalFilter 对所有路由生效；② getOrder()=-100 早于转发；③ 白名单必须写「剥前缀后」路径（如 /auth/**），否则登录接口被自己拦截；④ 必须删除外部伪造的身份头再写自身结论，防冒充。

4. account-service（账号服务 · 8081）

典型「网关统一认证 + 本地布隆防穿透」账号服务。Controller 薄层只收参与封装 Result，业务全在 UserServiceImpl，落库走 MP，密码 BCrypt，token 用 common 的 JwtUtil。

文件类型作用
AccountServiceApplication.java启动类@SpringBootApplication + @MapperScan 扫描 mapper 包。
bloom/UserBloomFilter.java组件Redis 上的用户名布隆过滤器（key bloom:user:username，100 万/0.01）防缓存穿透；注入 UserMapper 而非 Service（避循环依赖）；Redis 不可用降级（读失败返回 true、写失败记账）。
config/JwtConfig.java配置把 common 的 JwtUtil 注册为 Bean。
config/MybatisPlusConfig.java配置分页插件 PaginationInnerInterceptor + MetaObjectHandler 自动填充 createTime/updateTime。
config/RedissonConfig.java配置开启 Redisson 懒初始化（lazyInitialization），Redis 挂了也不影响启动。
controller/AuthController.java控制器/auth：POST /register、POST /login；入参 @Valid，返回 Result。
controller/UserController.java控制器/user/profile：只从网关透传的 X-User-Id/X-Username 头读身份原样回显（演示网关透传）。
dto/LoginRequest.javaDTO登录入参（username/password，@NotBlank）。
dto/LoginResponse.javaDTO登录出参（token/tokenType/userId/username/nickname，不含密码）。
dto/RegisterRequest.javaDTO注册入参（username 4-20 / password 6-32 / nickname ≤20）。
entity/User.java实体t_user ORM：雪花主键、BCrypt 密码、逻辑删除、自动填充时间。数据中枢。
handler/GlobalExceptionHandler.java切面@RestControllerAdvice：BusinessException / 校验失败 / 兜底 → Result。
mapper/UserMapper.javaMapperextends BaseMapper<User>，单表 CRUD。
service/UserService.java接口业务接口：register / login / getByUsername。
service/impl/UserServiceImpl.java实现核心：注册（布隆判重 → BCrypt → 落库 → add 布隆）；登录（布隆前置拦截 → 统一报错防枚举 → 签发 token）。
resources/application.yml配置应用名、Nacos 导入（common.yaml 先 → account-service.yaml 后）、本地 jwt.secret。
resources/sql/user.sql建表库 project0914 + t_user（username 唯一索引是并发防重复注册最终保障）。

5. dish-service（菜品服务 · 8082）

最大模块：AI 异步生成菜品 + ES 检索 + 发布同步 + 互动（收藏/评分/评论）+ 榜单。不对外暴露，请求经网关、身份从 X-User-Id 头读取。下分若干子包。

5.1 Controller 层（5 个 @RestController）

文件路由作用
DishGenerateController/ai生成门面：提交/轮询任务、调序、取消、删除任务、菜品详情、队列快照。
DishInteractionController/ai收藏（增/删）、评分、评论、我的菜品、我的收藏。
DishPublishController/ai发布/撤回、发布前检查、POST /es/reindex、食材转正接口（运维）。
DishRankController/ai/rank榜单：GET ?type=hot|top|latest，只统计已发布。
DishSearchController/search检索：POST /search（网关 StripPrefix=2 后路径为 /search）。
handler/GlobalExceptionHandler切面@RestControllerAdvice：异常 → Result（生成失败不在此，归宿是写 error_msg）。

5.2 Service 层

文件作用
DishGenerateService生成门面：submit（立即返回 + 单飞去重 signature + 入队）、myTasks、cancel、deleteTask、move、detail（草稿仅创建者可见）、queueSnapshot。
DishInteractionService收藏/评分/评论/我的列表：collectCount 按明细重算；recomputeRating 用 Java 算威尔逊下界（与 ES 口径一致）；requireVisibleDish 草稿权限校验。
DishPublishService发布闸门：check（步骤≥3、食材≥2、有热量、不重名）；publish/unpublish（@Transactional 发 DishPublishedEvent）；tryAutoPublish 失败只记日志。
DishRankService榜单：内部 enum RankType（hot/top/latest），手写 SQL 只统计 status=1 且自写 deleted=0。
DishSearchService召回中枢：参数规范化（ID/名字两互斥桶）→ ES 召回 → 应用层精排 → 直出判定（覆盖率≥0.8 且评价≥10 且威尔逊≥0.84）→ 组装结果。
IngredientResolver食材归一化（ID→标准名→别名→保留原文），读 IngredientMapper。
IngredientCandidateService表外食材候选：recordUsage（绝不抛异常）、promoteReady（转正四步 + 重写索引）。

5.3 ai 异步生成子系统

文件作用
DishGenerator（接口）生成器抽象，唯一与「用哪个模型」相关处；generate(Input)→Result。
AiDishGenerator实现：调本地 Ollama；四道约束（系统提示词→format=json→反序列化→校验器逐字段→失败拼回提示词重试 1 次）；本地按「食材×用量」核算热量与 AI 对比（nutritionVerified）。
DishDraftValidator草稿机器校验（第三道防线），每条报错具体，拼回重试提示词。
DishDraftWriter草稿落库（拆独立类保证 @Transactional 经代理生效）；记食材候选 usage；草稿态 status=0。
DishTaskQueue内存调度队列：submit/cancel/move/position；调度线程 + worker 线程池 + 单锁；单用户上限、取消权限内部校验；@PreDestroy 关池。不碰 DB、不认识 AI。
DishTaskExecutor（接口）/ DishGenerationExecutor队列回调的纯业务编排：置生成中→读快照→调生成器→落草稿→试自动发布→置终态；异常兜住写 error_msg 防僵尸任务。
AiTaskStatus / CancelOutcome / EnqueueResult枚举/记录：任务状态（0-5）、取消结果（区分真省资源 vs 逻辑取消）、入队结果。
GenerateProperties / QueueProperties配置：生成（maxAttempts=2、temperature 等）/ 队列（concurrency 默认1、maxPerUser=5）。
AiProbeControllerSpring AI 兼容性探针（可删），用 ObjectProvider 懒取 OllamaChatModel。

5.4 es 同步子系统（与发布解耦）

文件作用

5.5 entity / dto / mapper（数据层）

entity 全部 @TableName + @TableLogic；dto 多为 Lombok @Data 传输对象；mapper 多继承 BaseMapper，少数含手写 SQL。

文件类型作用

entity/Ingredient / IngredientCandidate实体食材主数据（每100g营养基准）/ 表外食材候选（攒够阈值转正）。
dto/*（16 个）DTODishDraft/DishGenerateRequest/Payload、DishSearchRequest、DishRecallResult、DishCardView、DishDetailView、DishItem、DishTaskView、IngredientRef、DishStep、RateRequest、CommentRequest、CollectResult、RatingSummary 等，承载前后端传输与视图模型。

9. 数据库核心表关系总览

MySQL 是 source of truth，ES 只是检索副本。发布经 @TransactionalEventListener(AFTER_COMMIT) 同步写索引，每日 04:00 全量兜底。

表职责关键约束
t_user（account）用户（username 唯一、BCrypt 密码、逻辑删除）uk_username
t_ingredient食材主数据（每100g营养基准），归一化与营养计算基准unique(name)，id 101~188
t_dish菜品主表（草稿/已发布共表，status 区分）idx_pool(status,rating_wilson)、uk_name_creator
t_dish_ingredient菜品-食材明细（倒排召回 + 营养唯一数据源）ingredient_id→t_ingredient（可空=表外）
t_tag / t_dish_tag标签主数据 + 菜品标签关联（召回过滤/加权）—
t_dish_rating评分（一人一票）uk_dish_user
t_dish_comment评论（可多条，不计分）—
t_dish_collect收藏（恢复式）uk_dish_user + 逻辑删除
t_ai_generate_taskAI 生成任务（单飞去重/频控）request_signature（MD5）
t_ingredient_candidate表外食材候选（攒够阈值转正）use_count
t_user_ingredient_pref用户食材偏好（排序加权，已建表未启用）—

一致性约定：主键统一雪花 ID，序列化全部 Long→String（防 JS 精度丢失导致详情页 404）；所有推荐池查询必须带 status=1 + deleted=0，杜绝草稿泄漏与已删除数据回流。

# 榜单与推荐重构方案

> 2026-10-07 复核后重写。所有阈值均用库内真实数据标定（112 道已发布菜），不拍脑袋。
> 现状实现见 `docs/cold-start-design.md`，本文是它的替代方案。

---

## 1. 实测证据：现在的设计坏在哪

### 1.1 「冷启动榜」里全是老菜

按 `dish_score` 降序取前 10，看菜龄：

| 菜名 | dish_score | 菜龄 |
|---|---|---|
| 红烧带鱼 | 86.91 | **130 天** |
| 松露番茄鸡蛋 | 85.61 | 22 天 |
| 凉拌菠菜 | 84.92 | **93 天** |
| 油焖大虾 | 83.57 | **153 天** |
| 醋溜白菜 | 83.03 | 58 天 |
| 蒜蓉粉丝蒸虾 | 82.16 | **95 天** |

**Top10 里 4 道是 60 天以上的老菜。** 榜名叫「冷启动」，排的却是综合得分——
而得分高的必然是积累了大量评分和互动的老菜。名字和内容完全对不上。

根因：`dish_score` 是**累积量**，新菜天然吃亏。实测菜龄 0~9 天的 11 道新菜
`avg_score = 46.9`，而 20 天以上的各档全在 72~78。新菜在这套算法下永远上不了榜。

### 1.2 置信系数形同虚设

`dish_score` 用 `LEAST(1, rating_count / min_score_count)` 做小样本折扣，演示档 `min-score-count = 3`。

```
110 道菜里 108 道 rating_count >= 3   →   avg_confidence = 0.982
```

**平均置信系数 0.982，等于这一项没加。** 实测 `rating_count` 均值 31.3、最大 75，
阈值 3 相对真实分布低了一个数量级。

### 1.3 老菜不掉榜（马太效应）

热门榜 `collect_count*3 + rating_count*2` 是纯累积量，无衰减。
实测 110 天以上的菜 `avg_collect = 20.5`，和 20~29 天那批的 24.4 几乎持平——
老菜靠历史存量稳稳占榜，新菜（0~9 天 `avg_collect = 13.7`）没有出头路径。

### 1.4 高分榜与冷启动榜口径不一致

| 榜 | 小样本处理 |
|---|---|
| 高分榜 | `rating_wilson`（威尔逊下界） |
| 冷启动榜 | `rating_avg/5 × 线性置信系数` |

两榜对同一件事用两套算法，同一道菜在两个榜的相对位置可能对不上。

### 1.5 三个真 bug

| # | 位置 | 问题 |
|---|---|---|
| 1 | `countRated()` | 缺 `rank_level >= 2`，与 `selectTopRank` 不一致 → total 虚高、尾部空页 |
| 2 | `selectHotRank` / `selectLatestRank` | 未过滤 `rank_level` → 新菜可绕过冷启动直接登榜；且 ES 只召回 `rankLevel=2`，出现「榜单有、搜索搜不到」 |
| 3 | `reportView` | 只在推荐流入口调用，是互动率的分母；而 like/cook/collect 来自全入口 → 分子全量、分母单入口，互动率系统性虚高 |

## 2. 新设计：一个质量分 + 三个切片

核心变化：**不再让四个榜各攒一套排序**，而是先定义唯一的「这道菜有多好」，
再让各榜成为它的不同投影。

### 2.1 统一质量分 `quality`（0~100）

```
rating_term      = rating_wilson × 100
interaction_raw  = (like_count + collect_count*2 + cook_count*3) / view_count
interaction_term = LEAST(1.0, interaction_raw / 0.4) × 100
quality          = 0.65 × rating_term + 0.35 × interaction_term
```

**为什么用 `rating_wilson` 换掉 `(rating_avg/5) × 置信系数`** —— 三条实测依据：

| 对比项 | 威尔逊 | 平均分/5 | 结论 |
|---|---|---|---|
| 实测范围 | 0.494 ~ 0.794 | 0.746 ~ 0.962 | 威尔逊下限更低，真的惩罚了小样本 |
| 区分度（极差） | **0.300** | 0.216 | 威尔逊排得更开 |
| 小样本处理 | 公式内建 | 靠置信项（实测失效，见 §1.2） | 威尔逊不需要额外参数 |

且换完之后**与高分榜口径统一**，两榜不再各说各话。

**互动率基准仍取 0.4**（不变，它是用真实数据标定的）：
实测 `interaction_raw` 最小 0.115、均值 0.233、最大 0.375，
除以 0.4 后落在 0.29 ~ 0.94，均值 0.58，区分度良好。

**权重 0.65 / 0.35 的理由**：评分是显式反馈（用户主动表达好恶），
互动是隐式反馈（点一下就走），显式信号更可信，故占大头。
原来是 0.6 / 0.4，微调是因为威尔逊的取值范围比 `avg/5` 更低，
不给评分项多一点权重的话，好菜会被互动量大的菜压过去。

**算出来是什么分布**（按实测均值估算）：

```
quality 均值 ≈ 0.65 × 67.0 + 0.35 × 58.0 = 63.9
quality 范围 ≈ 42（差）~ 84（好）
```

### 2.2 三个榜

| 榜 | 排序键 | 语义 |
|---|---|---|
| 高分榜 | `quality DESC` | 内容质量，不掺时间 |
| 热门榜 | `hot DESC`（见 §2.3） | 正在被多少人喜欢 |
| 新秀榜 | `quality DESC` + 30 天时间窗 | 近期新菜里最好的 |
| 最新榜 | `publish_time DESC` + `quality >= 50` | 刚出锅，但滤掉残次品 |

**「冷启动榜」取消，改名「新秀榜」并加时间窗** —— 这样它才名副其实。
冷启动**机制**（推荐池 → 晋级 → `rank_level=2`）全部保留，只是退居后台，
不再占一个用户可见的 tab。

最新榜加 `quality >= 50` 门槛：现在的纯时间排序会把刚发布的残次品直接顶到第一位。

### 2.3 活跃度衰减：解决马太效应的关键

需要新增一个字段 `last_interact_time`（每次 like/collect/cook/rating/view 时更新）：

```sql
ALTER TABLE t_dish
  ADD COLUMN last_interact_time DATETIME NULL COMMENT '最近一次互动时间（活跃度衰减用）'
  AFTER update_time;
```

然后热门榜：

```
hot_raw = collect_count*3 + like_count*1 + cook_count*2 + rating_count*2
decay   = EXP(-LN(2) / 30 × DATEDIFF(NOW(), last_interact_time))
hot     = hot_raw × decay
```

半衰期 30 天：最后一次被互动是 30 天前 → 热度打五折；昨天刚有人互动 → 接近满值。

**为什么这样能解决马太效应**：
老菜如果持续有人互动，`last_interact_time` 一直是新的，decay 保持高位，不掉榜（合理）；
老菜无人问津，decay 一路衰减，自然退场（新菜才有位置）。
这比「按发布时间衰减」更准确——衰减的应该是**行为的新旧**，不是菜的新旧。

`like`/`cook` 权重为什么能给进来了：现在 `like_count`、`cook_count` 两个字段攒了却没进任何榜单，
只用 `collect` 和 `rating_count`，热度定义是残缺的。

## 3. 推荐流：从「分档」改成「打分」

现状是三级硬分档（全匹配 / 部分匹配 / 随机），档内 `ORDER BY RAND()`。
问题：档内无质量信号，命中 4 种和命中 1 种混在一起随机排，`page` 参数收了不用。

改成一次召回 + 显式打分：

```
match_score  = (命中食材数 / 用户选中数) − 0.1 × 缺料数      ← 缺料口径复用 ES 侧那套
quality_norm = quality / 100
freshness    = EXP(-LN(2) / 14 × DATEDIFF(NOW(), publish_time))

feed_score = match_score × 0.5 + quality_norm × 0.3 + freshness × 0.2
```

「完全匹配 / 部分匹配」**降级为前端角标**（本来就是答辩加分项），不再参与取数。

## 4. 落地顺序

| 优先级 | 改动 | 工作量 | 依赖 |
|---|---|---|---|
| **P0** | 修 §1.5 三个 bug | ~20 行 | 无 |
| **P1** | `dish_score` 改威尔逊（改一条 SQL + 配置项） | ~15 行 | P0 |
| **P2** | 加 `last_interact_time`（迁移 + 5 处更新点） | 半张表 | 无 |
| **P3** | 冷启动榜 → 新秀榜；热门榜启用衰减；最新榜加门槛 | ~40 行 | P1、P2 |
| **P4** | 推荐流打分制 | ~60 行 | P1 |

**P0/P1 可以一起做，改动都在 SQL 和 Service 里，不动表结构。**
P2 之后才有真正的热度衰减。

改完必须重跑的验证：
- `POST /ai/es/reindex`（评分口径变了，索引里的 `dishScore` 要同步）
- `es/eval/run-ranking-experiment.py`（排序实验结论会变）
- 现有 `dish_score` 数值会整体下移（威尔逊比 `avg/5` 低），这是预期的

## 5. 论文里怎么写

1. **统一质量分**：以威尔逊下界处理评分的小样本偏差，以量程归一后的互动率刻画隐式反馈，
   两者加权得到唯一的内容质量度量——避免多榜单各自定义排序口径导致的结论冲突。
2. **活跃度衰减**：以半衰期函数对累积热度做时间折扣，衰减依据是最近一次互动时间而非发布时间，
   在保留长尾优质内容的同时为新增内容让出曝光位，缓解累积量排序的马太效应。
3. **冷启动与榜单解耦**：分级曝光（推荐池 → 晋级）作为后台流量分配机制，
   对用户的呈现是「新秀榜」这一时间窗切片，机制不直接暴露为产品概念。
4. **阈值可配置**：全部阈值经 Nacos 下发，并给出按环境分档的对照表。
